# runtime-probe — стенд разведки агентных сред

Отвечает на вопросы, которые нельзя решить чтением документации: **что конкретная среда на самом деле
исполняет, что доставляет и чему подчиняется**. Claude Code CLI, Cowork, Claude Desktop, Codex и всё,
что появится дальше — один и тот же зонд, сопоставимые результаты.

Стенд нужен потому, что документация и чужие тикеты описывают заявленное поведение, а не текущее:
вывод «хуки в Cowork не работают», прожитый нами полгода как факт, замером не подтвердился.

## Что уже умеет

### Проба хуков

Зонд на все 10 событий жизненного цикла, разделяющий **три уровня отказа** — их обычно путают:

1. **хук запустился** — есть запись в логе;
2. **его вывод дошёл до модели** — агент называет кодовое слово из `additionalContext`;
3. **его решения действуют** — команда с маркером `HOOKPROBE_DENY` реально заблокирована.

Среда может исполнять хук и игнорировать его stdout; может доставлять контекст и не подчиняться `deny`.
Одна проверка этого не различает, поэтому их три.

Два канала доставки живут отдельно и проверяются независимо:

| Канал | Где | Что проверяет |
|---|---|---|
| Плагин | [plugins/hook-probe/](plugins/hook-probe/) | доезжают ли хуки, упакованные в плагин из маркетплейса |
| Проект | [project-scoped/](project-scoped/) | читает ли среда `.claude/settings.json` рабочей папки |

Логи каналов не смешиваются: плагинный пишет в `~/.hook-probe/`, проектный — рядом с собой.

## Установка плагина

```
/plugin marketplace add https://github.com/JazzShapka/runtime-probe
/plugin install hook-probe@hook-probe-marketplace
```

Локально или там, где слэш-команды `/plugin` нет:

```
claude plugin marketplace add https://github.com/JazzShapka/runtime-probe
claude plugin install hook-probe@hook-probe-marketplace
```

После установки — **перезапустить сессию**: хуки регистрируются при старте, иначе `SessionStart` не поймать.

## Прогон

В новой сессии: `/hook-test` — сценарий из четырёх шагов, затем `/hook-report` — таблица событий
и срез окружения (`CLAUDE_*`, host, cwd, платформа).

❗️ Шаг с `ask` подтверждает **человек**: агент не видит слоя разрешений и уверенно сообщает, что диалога
не было, даже когда он показан. Это воспроизвелось в каждой среде — считать отчёт агента об UI-эффектах
данными нельзя.

## Что дальше

- **Codex** — тот же зонд под его механизм хуков; форма входа отличается (нет поля пути, окружение вычищено).
- **Проба доставки** — установка плагина в разных системах: какие компоненты доезжают (skills, commands,
  agents, hooks, MCP), а какие отбрасываются при переносе.
- **Проба разрешений** — как среда обходится с `ask`, allow-листами и авто-режимами.

Новая проба заводится папкой рядом с существующими: свой канал доставки, свой лог, свой раздел здесь.
