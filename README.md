# hook-probe — плагин-зонд механизма хуков

Отвечает на вопрос: **исполняются ли хуки в конкретной обвязке Claude** — CLI, Cowork,
IDE — и если да, доходит ли вывод хука до модели и до движка разрешений.

Доставляется как плагин, потому что в облачной сессии (Cowork) `.claude/settings.json`
из подключённой локальной папки не читается: сессия живёт в песочнице со своей ФС.
Плагин же ставится внутрь этой сессии.

## Состав

- `plugins/hook-probe/hooks/hooks.json` — все 10 событий на один скрипт.
- `plugins/hook-probe/scripts/probe.py` — пишет лог в `~/.hook-probe/hook-probe.jsonl`
  (внутри той среды, где живёт сессия) и возвращает видимый эффект.
- `plugins/hook-probe/scripts/report.py` — таблица «событие → сработал / не виден»
  плюс срез окружения: `CLAUDE_*` переменные, cwd, host, платформа.
- Команды `/hook-test` (прогнать сценарий) и `/hook-report` (показать результат).

## Установка

```
/plugin marketplace add <git-url этого репозитория>
/plugin install hook-probe@hook-probe-marketplace
```

Локально то же самое из каталога:

```
claude plugin marketplace add ~/projects/hook-probe-plugin
claude plugin install hook-probe@hook-probe-marketplace
```

После установки — **перезапустить сессию**: хуки регистрируются при старте,
и `SessionStart` иначе не поймать.

## Прогон

В новой сессии: `/hook-test`, затем `/hook-report`.

## Как читать

- **лог не создан** — хуки плагина в этой среде не запускаются вовсе;
- **лог есть, кодового слова модель не видела** — хук исполняется, но stdout в контекст не идёт;
- **`echo HOOKPROBE_DENY` выполнился** — управляющие решения хуков игнорируются: гварды
  (запрет коммита, защита файлов) в такой среде не защищают;
- **`Notification` / `PreCompact` не видны** — часто просто не наступил повод, не отказ.

Три уровня отказа различаются, и именно поэтому проверок три, а не одна.
